## Notes

- Known limitation: HTML labels (`foreignObject`) from portograph make the SVG about 180 KB after sanitising. The demo panel shows the badge `53 HTML labels (foreignObject). Set convertToSvg=1 on labels for smaller, native text.` The `convertToSvg=1` setting in the generator would cut the size to a few KB.
- Frontend sandbox, manual pass. I ran two extra Grafana containers (12.4.13 and 13.2.4) with the same `dist/` and `provisioning/`.
  - The environment variable in the plan (`GF_PLUGINS_ENABLE_FRONTEND_SANDBOX_FOR_PLUGINS`) does not enable the sandbox. `/api/frontend/settings` showed `enableFrontendSandboxForPlugins: ['']`.
  - The working settings are `GF_SECURITY_ENABLE_FRONTEND_SANDBOX_FOR_PLUGINS=simnv-drawiomap-panel` and `GF_FEATURE_TOGGLES_ENABLE=pluginsFrontendSandbox`. Settings then showed `pluginsFrontendSandbox: True` and `enableFrontendSandboxForPlugins: ['simnv-drawiomap-panel']`.
  - View mode works in the sandbox on both versions. 2 panels render, 24 link halves (22 with status `ok`), 10 sparklines, no page errors. The 2 view tests and the 2 link tests pass on both versions.
  - Known limitation: the editor does not work in the sandbox. Verified on 13.2.4 with debug logs. Two sandbox rules block the reply channel to the draw.io frame:
    1. The sandbox forbids `iframe.contentWindow`. A read throws `iframe.contentWindow is not allowed in sandboxed plugins` (Grafana `public/app/features/plugins/sandbox/distortions.ts`, `distortIframeAttributes`).
    2. A read of `event.source` throws `SecurityError: Blocked a frame ... from accessing a cross-origin frame`. near-membrane cannot wrap the cross-origin editor window.
  - The panel gets the editor messages (origin and payload are readable), but it has no window object to send replies to. The draw.io embed protocol needs these replies (`configure`, `load`, `export`).
  - Behaviour now: the modal validates messages by origin and JSON event shape. It compares the sender only when the sender is readable. In the sandbox, the first editor message sets `data-dmap-editor-blocked="true"` on the modal and shows the alert "The draw.io editor cannot start". The modal does not stay silently in phase `init`.
  - Work-around: remove `simnv-drawiomap-panel` from `enable_frontend_sandbox_for_plugins`. A draw.io server on the Grafana origin (reverse proxy) can make `event.source` readable. This is not tested.
  - Manual check: `docker compose run --rm -d --name dmap-sandbox -p 127.0.0.1:3014:3000 -e GF_SECURITY_ENABLE_FRONTEND_SANDBOX_FOR_PLUGINS=simnv-drawiomap-panel -e GF_FEATURE_TOGGLES_ENABLE=pluginsFrontendSandbox grafana13`, then open the editor at `http://localhost:3014`.
  - `tests/no-drawio.spec.ts` fails in the sandbox on its iframe count (1 iframe found, not inspected). The sandbox itself can add an iframe. The check for requests to the editor origin passes.
